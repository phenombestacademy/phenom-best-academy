## 3. Google + Supabase
Supabase now uses publishable/secret key terminology. The browser should receive only the publishable key (or the older anon key if the project still exposes it). Secret/service-role keys stay server-side.

For Google sign-in:
1. Supabase Dashboard → Authentication → Providers → Google.
2. Create/select a Google Cloud project.
3. Google Auth Platform → Clients → Create OAuth Client → Web application.
4. Add your production site as an authorised JavaScript origin.
5. Add the Supabase callback URL shown by the Supabase Google provider page as the authorised redirect URI.
6. Copy Google Client ID + Client Secret into Supabase's Google provider configuration.
7. Set the Supabase Site URL to your production Academy URL.

The site code already calls Supabase Google OAuth; Google credentials must be created in Google's console and cannot be safely generated by the website code.

## 4. Where the Supabase URL / project ref / publishable key come from
Supabase Dashboard → Settings → API.

- Project URL: `https://YOUR_PROJECT_REF.supabase.co`
- Project ref / ID: the `YOUR_PROJECT_REF` part.
- Publishable key: the browser-safe key shown in API Keys.

Do NOT put the secret/service-role key in GitHub or a `VITE_*` variable.

## 5. Payment methods
V4 can route checkout through:
- Flutterwave
- Paystack
- Stripe
- Interswitch
- Direct bank transfer instructions

The actual merchant account must be activated by the merchant. V4 does not invent or expose credentials.

Flutterwave's current Nigeria payment methods include card, bank transfer, bank account, USSD, OPay, NQR and eNaira, with card networks including Visa, Mastercard, American Express, Verve and Afrigo where supported.

Paystack supports Visa, Mastercard, Verve and international cards, plus transfer, bank and USSD channels where enabled.

Interswitch supports card, transfer, USSD, wallet and Google Pay where enabled.

Stripe can be used where the Academy's Stripe account is eligible for the desired market/currency.

### Direct bank transfer
Super Admin should enter the verified Academy account name, bank, account number and instructions in the payment-provider settings. The public site will show only those published payment details. For stronger automatic reconciliation, use Flutterwave/Paystack/Interswitch transaction-specific virtual accounts rather than asking customers to send an unreferenced transfer.

## 6. AI routing
V4 provides a hidden server-side AI router. Customers do not see provider names.

Supported direct providers:
- OpenAI API
- Gemini API with optional Google Search grounding

Optional self-hosted gateway:
- LiteLLM or another OpenAI-compatible internal gateway can be placed behind `AI_ROUTER_URL`.

The router chooses a provider based on request mode and availability. If no live provider is configured, the existing Academy fallback remains available for the supported local learning tools.

Important: “free/open-source” gateway software does not make the underlying commercial model API free. API keys and model usage may still incur charges.

## 7. Email
V4 uses Resend through a Supabase Edge Function for direct Academy emails. Verify the Academy's sending domain in Resend before production sending.

The Academy can store subscriber email addresses and display user emails to Super Admin, but passwords are never exposed. Supabase stores password hashes, not plaintext passwords.
